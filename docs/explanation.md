## 1. Обзор проекта

### 1.1 Что такое SalesAI?

**SalesAI** — это интеллектуальная SaaS-платформа для контроля качества продаж и обучения сотрудников. Платформа автоматизирует анализ звонков, используя технологии распознавания речи (STT — Speech-to-Text) и большие языковые модели (LLM) для предоставления действенных аналитических данных.

### 1.2 Основные цели проекта

- **Автоматизация контроля качества**: Переход от случайной выборки звонков к 100% анализу всех звонков
- **AI-коучинг**: Предоставление продавцам автоматизированного ИИ-тренера с конкретными рекомендациями
- **Аналитика для руководителей**: Дашборды с метриками эффективности команды
- **Интеграция с CRM**: Автоматическая запись результатов анализа в AmoCRM

### 1.3 Пользовательские роли (RBAC)

| Роль | Уровень доступа | Описание |
|------|----------------|----------|
| **Супер-админ** | Системный | Управление компаниями-арендаторами, мониторинг системы |
| **Администратор компании** | Компания | Управление скриптами, пользователями, просмотр аналитики команды |
| **Продавец** | Индивидуальный | Просмотр только своих звонков, персональный дашборд |

## 3. Микросервисы и их назначение

### 3.1 Main API (Golang + Fiber)

**Порт:** 8080  
**Протокол:** HTTP REST, gRPC, WebSocket

**Основные responsibilities:**
- Аутентификация пользователей (JWT)
- Управление доступом на основе ролей (RBAC)
- CRUD-операции для звонков, пользователей, компаний
- Агрегация аналитических данных
- Real-time уведомления через WebSocket
- gRPC-коммуникация с Python-сервисами

**Структура проекта:**
```
services/main-api/
├── cmd/api/main.go              # Точка входа
├── internal/
│   ├── adapters/
│   │   ├── http/handlers/       # HTTP-контроллеры
│   │   ├── http/middleware/     # JWT, RBAC, логирование
│   │   ├── grpc/               # gRPC-клиенты
│   │   └── repositories/       # Репозитории PostgreSQL
│   ├── core/
│   │   ├── domain/              # Сущности (User, Call, Company)
│   │   ├── ports/              # Интерфейсы
│   │   └── usecases/           # Бизнес-логика
│   └── infrastructure/
│       ├── config/              # Конфигурация
│       ├── database/            # Подключение к БД
│       └── security/            # JWT-сервис
└── pkg/dto/                     # Data Transfer Objects
```

**Основные API-эндпоинты:**
- `POST /api/v1/auth/register` — Регистрация пользователя
- `POST /api/v1/auth/login` — Вход в систему
- `GET /api/v1/calls` — Список звонков с фильтрами
- `GET /api/v1/calls/:id` — Детали звонка
- `GET /api/v1/analytics/team-performance` — Аналитика команды
- `GET /api/v1/analytics/leaderboard` — Таблица лидеров
- `WS /api/v1/ws` — WebSocket для уведомлений

### 3.2 Sipuni Listener (Golang + Fiber)

**Порт:** 8081  
**Протокол:** WebSocket (клиент), HTTP

**Основные responsibilities:**
- Поддержание постоянного WebSocket-соединения с Sipuni (`wss://wss.sipuni.com/api`)
- Аутентификация с использованием API-ключа
- Получение событий о звонках (звонок поступил, answered, завершён)
- Создание записей о звонках в PostgreSQL
- Добавление задач в очередь BullMQ для обработки аудио

**Поток обработки событий:**
1. Подключение к Sipuni WebSocket
2. Отправка auth-сообщения: `{"type":"auth","body":{"key":"<API_KEY>"}}`
3. Прослушивание событий `notify` с данными о звонке
4. Извлечение данных: call_id, direction, from, to, record_url, timestamps
5. Создание записи о звонке в PostgreSQL
6. Добавление задачи в BullMQ: `audio_processing`

**Формат входящего события (Sipuni):**
```
json
{
  "type": "event",
  "action": "notify",
  "namespace": "api",
  "request": {
    "call_id": "external-sipuni-id",
    "event": "5",
    "dst_num": "222",
    "src_num": "77081996454",
    "timestamp": "1694535780",
    "user_id": "manager-123",
    "status": "completed",
    "call_record_link": "https://files.sipuni.com/.../record.mp3"
  }
}
```

**Формат задачи BullMQ:**
```
json
{
  "job_type": "audio_processing",
  "call_id": "uuid-generated",
  "company_id": "company-uuid",
  "audio_url": "https://...",
  "manager_id": "manager-123",
  "retry_count": 0,
  "max_retries": 3
}
```

### 3.3 Script Service (Golang + Python)

**Порт:** 8083  
**Протокол:** HTTP REST

**Основные responsibilities:**
- Загрузка скриптов продаж (DOCX/PDF) в MinIO
- Парсинг текстового содержания из документов
- Хранение распарсенного текста в PostgreSQL
- Предоставление API для получения скриптов AI-сервисом

**Основные эндпоинты:**
- `POST /api/v1/scripts` — Загрузка скрипта
- `GET /api/v1/scripts/:company_id` — Список скриптов компании
- `GET /api/v1/scripts/:id/download` — Скачивание файла скрипта
- `DELETE /api/v1/scripts/:id` — Удаление скрипта

**Python-парсеры для документов:**
- `scripts/parse_docx.py` — Парсинг DOCX-файлов
- `scripts/parse_pdf.py` — Парсинг PDF-файлов

### 3.4 STT Service (Python + FastAPI)

**Внутренний порт:** 5001  
**Протокол:** gRPC Server + BullMQ Consumer

**Основные responsibilities:**
- Потребление задач из очереди BullMQ (`audio_processing`)
- Загрузка аудио по URL
- Конвертация аудио в формат 16kHz WAV
- Диаризация спикеров (Pyannote)
- Распознавание речи (STT):
  - **Локально**: WhisperX
  - **Облако**: OpenAI Whisper API или Google Gemini STT
- Сохранение транскрипта в PostgreSQL
- Публикация события `transcript_ready` в Redis Stream

**Поток обработки:**
1. Получение задачи из очереди BullMQ
2. Загрузка настроек компании (выбор STT-провайдера)
3. Скачивание аудио в `/tmp`
4. Конвертация в 16kHz WAV
5. Диаризация спикеров (Pyannote)
6. STT-распознавание (WhisperX/OpenAI/Gemini)
7. Объединение результатов диаризации и транскрипта
8. Сохранение JSON-транскрипта в PostgreSQL
9. Удаление аудио из `/tmp`
10. Публикация события `transcript_ready` в Redis Stream

**Переменные окружения:**
- `STT_PROVIDER` — "openai" | "gemini" | "local"
- `OPENAI_API_KEY` — API-ключ OpenAI
- `GOOGLE_API_KEY` — API-ключ Google

### 3.5 AI Analytics Service (Python + FastAPI)

**Внутренний порт:** 5002  
**Протокол:** gRPC Server + Redis Stream Consumer

**Основные responsibilities:**
- Потребление событий `transcript_ready` из Redis Stream
- Получение транскрипта и скрипта из базы данных
- LLM-анализ:
  - **OpenAI**: GPT-4 анализ
  - **Google Gemini**: Gemini Pro анализ
- Расчёт метрик:
  - Quality Score (оценка качества)
  - Script Match (процент соблюдения скрипта)
  - Error Count (количество ошибок)
  - Talk Time Ratio (соотношение времени разговора)
- Расчёт KPI по формуле
- Сохранение отчёта в PostgreSQL
- (Опционально) Запись результатов в AmoCRM

**Метрики анализа:**
- **Quality Score (0-100)**: Общее качество звонка
- **Script Match (0-100)**: Процент следования скрипту
- **Talk Time Ratio**: Соотношение времени менеджер/клиент
- **Error Count**: Количество отклонений/ошибок
- **KPI**: Композитный показатель

**Формула расчёта KPI:**
```
KPI = (Quality * 0.4 + ScriptMatch * 0.4 + ErrorsFree * 0.2) * (Duration / 60)
```

- **Режим API**: HTTP-эндпоинты для ручной синхронизации (/health, /sync, /sync/blocking)

## 5. Взаимодействие между сервисами

### 5.1 Синхронная коммуникация (Request-Response)

```
Клиент → Nginx → Main API (8080) → PostgreSQL
Клиент → Nginx → Script Service (8083) → MinIO
```

### 5.2 gRPC-коммуникация

```
Main API (Go) ────gRPC───→ STT Service (Python)
Main API (Go) ────gRPC───→ AI Analytics (Python)
```

### 5.3 Событийно-ориентированная коммуникация

```
Sipuni Listener (WebSocket)
        ↓
    PostgreSQL (Запись о звонке)
        ↓
    BullMQ Queue (Задача audio_processing)
        ↓
    STT Service (Обработка аудио)
        ↓
    Redis Stream (Событие transcript_ready)
        ↓
    AI Analytics (Анализ транскрипта)
        ↓
    PostgreSQL (Отчёт анализа)
        ↓
    WebSocket Hub (Уведомление клиента)
```

## 6. Поток данных

### 6.1 Полный pipeline обработки звонка

```
1. Sipuni (телефония) ──WebSocket-событие──→ Sipuni Listener
2. Sipuni Listener ──Создание звонка──→ PostgreSQL
3. Sipuni Listener ──Добавление задачи──→ BullMQ (Redis)
4. BullMQ ──Потребление задачи──→ STT Service
5. STT Service ──Загрузка аудио──→ Внешний URL
6. STT Service ──Конвертация аудио──→ 16kHz WAV
7. STT Service ──Диаризация──→ Pyannote
8. STT Service ──Транскрибация──→ WhisperX/OpenAI/Gemini
9. STT Service ──Сохранение транскрипта──→ PostgreSQL
10. STT Service ──Публикация события──→ Redis Stream
11. Redis Stream ──Потребление события──→ AI Analytics
12. AI Analytics ──Получение транскрипта──→ PostgreSQL
13. AI Analytics ──Получение скрипта──→ PostgreSQL/MinIO
14. AI Analytics ──LLM-анализ──→ OpenAI/Gemini
15. AI Analytics ──Расчёт KPI──→ Внутренний
16. AI Analytics ──Сохранение отчёта──→ PostgreSQL
17. AI Analytics ──Уведомление──→ Redis Pub/Sub
18. Redis Pub/Sub ──Потребление──→ Main API WebSocket Hub
19. WebSocket Hub ──Трансляция──→ Клиент
```

## 7. База данных

### 7.1 Мультисхемный подход

Система использует **мультисхемный подход** для изоляции данных:

| Схема | Назначение | Таблицы |
|-------|-----------|---------|
| `auth_schema` | Аутентификация и компании | companies, users |
| `calls_schema` | Звонки и аналитика | calls, transcripts, analysis_reports |
| `scripts_schema` | Скрипты продаж | scripts |
| `integrations_schema` | Интеграции | integrations |
| `logs_schema` | Логирование | processing_logs, notifications |

### 7.2 Основные сущности

```
companies (1) ──────┬────── (N) users
                    │
                    ├────── (N) scripts
                    │
                    ├────── (N) integrations
                    │
                    └────── (N) calls ──┬─── (1) transcripts
                                        │
                                        ├─── (1) analysis_reports
                                        │
                                        └─── (N) processing_logs

users (1) ────────────── (N) notifications
```

### 7.3 Таблицы базы данных

1. **`companies`**: Настройки арендаторов, статус подписки
2. **`users`**: Учётные данные, роли, связь с компаниями
3. **`scripts`**: JSON-определения скриптов продаж
4. **`integrations`**: OAuth-токены для AmoCRM
5. **`calls`**: Метаданные звонков (длительность, менеджер, ссылка, статус)
6. **`transcripts`**: Текст с таймстемпами (отдельная таблица для производительности)
7. **`analysis_reports`**: LLM-вывод (оценки, рекомендации)
8. **`notifications`**: Журнал отправленных уведомлений

## Заключение

SalesAI — это современная микросервисная платформа, построенная с использованием передовых технологий и лучших практик разработки. Архитектура обеспечивает:

- **Масштабируемость**: Каждый сервис может масштабироваться независимо
- **Надёжность**: Очередь BullMQ с механизмом повторных попыток
- **Производительность**: Асинхронная обработка аудио
- **Гибкость**: Поддержка нескольких STT и LLM-провайдеров
- **Безопасность**: JWT-аутентификация и RBAC
- **Мониторинг**: Интеграция с Prometheus и Grafana
